# Hisar Desktop

Wails v3 (pinned beta, see `WAILS_VERSION` in the root `Makefile`) with a Vue 3 + TypeScript frontend.

| Path | What |
|---|---|
| `vault/` | Go backend bound to the UI: session, lock/auto-lock, clipboard clearing, SSH Key items. No Wails import, so it is tested on any OS |
| `agent/` | SSH agent in the app: approval (Touch ID or in-app prompt), `~/.ssh/config` setup, agent status. No Wails import |
| `biometric/` | Touch ID and the macOS Keychain (cgo) |
| `main.go` | Wails app: window, clipboard, lock-event and approval-event adapters; starts the SSH agent |
| `frontend/src` | UI: `api.ts` (only file that calls the bindings), `store.ts` (state and actions), `components/` |
| `frontend/bindings` | Generated by `wails3 generate bindings` during every build; committed, and CI fails if a build changes them |
| `build/` | Platform build config (macOS, Linux) |

## Build and run on macOS

Requires Go 1.26+, Node 24 and Xcode command line tools.

```sh
make install-wails          # installs the pinned wails3 CLI into ~/go/bin
make package-desktop        # builds desktop/bin/Hisar.app (ad-hoc signed)
open desktop/bin/Hisar.app
```

For development with hot reload: `cd desktop && wails3 dev`.

To work on the design without a server, run the UI in a browser with sample data:

```sh
cd desktop/frontend && npm run preview:ui
# http://127.0.0.1:5180/?state=signed-out | locked | unlocked
# extra parameters: &vault=family &item=netflix &editor=create|edit|ssh-key &secretKey=1 &search=git
# SSH: &item=raspberry (SSH key) &settings=1 &approval=1 (in-app approval prompt) &agent=error &sshConfigured=1
```

The preview backend (`src/preview.ts`) is loaded with a dynamic import behind a build-time flag; `npm run check:bundle` (run in CI) fails if it ever ends up in the production bundle.

The app keeps its session in `~/Library/Application Support/hisar/desktop.json` (override with `HISAR_DESKTOP_STATE`) and the Secret Key in the macOS Keychain under the service `hisar`.

## SSH agent

Hisar is an SSH agent for the SSH keys in your vaults (design: `docs/DESIGN.md` §9.6).

1. Add a key: **+** → **SSH key**, then **Generate** (Ed25519, or RSA 4096 for old servers) or **Import** (paste an OpenSSH or PEM private key; a passphrase is only needed to import, the key is stored without it).
2. Copy the public key from the key's page (**Copy public key**) into GitHub or the server's `~/.ssh/authorized_keys`.
3. Settings → SSH agent → **Use Hisar for SSH**. This backs up `~/.ssh/config` to `~/.ssh/config.hisar-backup-<timestamp>` and adds at the top:

   ```
   # Added by Hisar: use the Hisar SSH agent
   Host *
     IdentityAgent "~/.hisar/agent.sock"
   # End of Hisar section
   ```

   **Remove from SSH config** takes the section out again. To try it without changing the config: `SSH_AUTH_SOCK=~/.hisar/agent.sock ssh-add -l`.

The agent listens on `~/.hisar/agent.sock` while the app runs (`HISAR_SSH_AGENT_SOCKET` overrides the path) and offers keys from all your vaults only while Hisar is unlocked. The first time a program (`ssh`, `git`, …) uses a key, Hisar asks for Touch ID, or shows an Allow/Deny prompt in its window on Macs without Touch ID (denied after 60 seconds). Approvals last until Hisar locks.

## Tests

```sh
make test                     # includes desktop/vault, desktop/agent and desktop/biometric unit tests
make test-desktop-frontend    # vue-tsc type-check and Vitest component tests
make test-end-to-end          # includes the desktop backend against a real server
```
